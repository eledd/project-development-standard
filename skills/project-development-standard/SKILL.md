# 项目开发流程与公共规范

一个 Skill 同时提供开发流程和可公开复用的代码、Java 与文档基础规范，按任务读取，不要求每个项目复制整套公共规则。项目只补充业务约束、工具配置与明确的差异；本包不包含内部协议、固定框架或个人目录。仅安装或加载本 Skill 不授权提交、推送、删除、部署、安装依赖、修改钩子或生产操作。

## 1. 发现项目规则

1. 确认目标仓库、任务范围、当前分支和工作区改动；保留已有内容，不因整理规范顺带修改其他项目。
2. 读取适用于目标文件的 `AGENTS.md` 及其实际引用的规则；检查子目录是否有补充约束。父级规则只在当前环境实际可读取且确实适用时使用，不能假定团队具有相同的本地目录布局。
3. 从项目入口与配置发现技术栈、目录、文档索引、模板和检查命令；不要求项目必须存在特定目录、配置文件或检查脚本。仅加载当前任务相关资料。
4. 按任务汇总规则来源、关键约束、允许的验证方式和缺失项。遵循当前工具指令层级；基础格式与项目已有明确配置冲突时沿用项目配置，避免无关格式迁移。涉及授权、安全、兼容性或业务含义的冲突先确认，不能以“项目优先”为由静默放宽安全要求。
5. 项目没有专用规范时，使用本 Skill 的基础规范并保持存量风格；涉及协议、安全或数据约束的未知项先确认。不因缺少项目规则而跳过基础规范，也不宣称本包等于尚未取得的团队全部标准。

## 2. 选择流程

- **需求与技术方案**：按[需求与方案流程](references/change-workflows.md#需求与方案任务)核查现状、约束、设计取舍和验收边界；用户仅要求讨论、设计或计划时，不自动修改代码或创建文档。
- **代码开发、修复、重构或代码评审**：读取[编码规范](references/coding-standard.md)，再按[代码流程](references/change-workflows.md#代码任务)核查调用链与兼容性；涉及 Java 时另读[Java 规范](references/java-backend.md)。非 Java 任务不读取 Java 规范。
- **文档编写、整理或文档评审**：读取[文档规范](references/documentation.md)，再按[文档流程](references/change-workflows.md#文档任务)确定用途、核对实现并维护引用。代码任务只在需要修改文档时追加读取。
- **联调、验收与发布准备**：按[交付核查流程](references/change-workflows.md#联调验收与发布准备)核对契约、环境与上线前置条件；发布准备不等于已获部署授权。
- **认证、安全或持久层变更**：再按[高风险链路检查](references/sensitive-chains.md)读取相关部分；其他任务不强制加载。
- **仅审查**：先报告有依据的问题与验证边界，不因加载本 Skill 自动修改代码或创建评审文件。

可结合当前环境已有的诊断、重构等专用能力；缺少某个工具时使用可用替代方案并说明，不将特定工具或另一 Skill 作为强制依赖。

## 3. 约定改动与验证边界

1. 修改前定位实现、调用方、数据模型及配置读写位置；多模块或多端共享行为须继续查到最终消费方，不能只看入口。
2. 说明需要修改的文件、必须保持的存量行为、异常边界与验证方式。小任务使用简短说明，不机械生成方案文件。
3. 现有调用方依赖的签名、序列化、错误语义和副作用视为兼容面；按项目规定隔离新增行为。确需破坏性变更时，先说明影响、迁移与回滚并取得明确确认。
4. 检查测试时限、环境、依赖、构建限制与当前授权，不因 Skill 推荐验证就运行项目禁止的命令。

## 4. 实施与交付

1. 执行本次已读取的公共规范及项目明确差异；沿用目标项目的分层与技术栈，不把另一项目的后端框架、前端规范或数据规则套过来。复杂逻辑与新增文档默认中文，项目明确要求其他语言时按已确认约定处理。
2. 按风险执行新行为与存量回归验证。模型、构造器、序列化及调用方变更需闭环核对；不要因单个调用点正确就宣称全链路可用。
3. 更新受影响的权威文档与索引；项目有模板时沿用，无模板时参考文档规范的最小内容骨架，不生成无关章节或全套文档。具体目录和业务协议由项目确定。
4. 仅运行已核实且获授权的检查入口；分清工作区、暂存快照及 CI 基线。没有检查工具时报告可执行的替代验证，不自动安装工具、修改暂存区或创建钩子。
5. 交付时说明实际改动、适用规范及必要项目差异、兼容性影响、执行过的验证和遗留问题；未执行的测试、批准、CI 接入、推送和部署不能写成完成。格式或链接检查通过不等于注释准确、业务通过或安全审查完成。
