# 项目开发规范执行流程

本 Skill 提供跨项目的执行流程，不内置某个团队的编码标准、目录约定或业务协议。具体标准来自目标项目，缺失时明确说明，不把示例或其他项目的规则当作默认要求。仅安装或加载本 Skill 不授权提交、推送、删除、部署、安装依赖、修改钩子或生产操作。

## 1. 发现项目规则

1. 确认目标仓库、任务范围、当前分支和工作区改动；保留已有内容，不因整理规范顺带修改其他项目。
2. 读取适用于目标文件的 `AGENTS.md` 及其实际引用的规则；检查子目录是否有补充约束。父级规则只在当前环境实际可读取且确实适用时使用，不能假定团队具有相同的本地目录布局。
3. 从项目入口与配置发现技术栈、目录、文档索引、模板和检查命令；不要求项目必须存在特定目录、配置文件或检查脚本。仅加载当前任务相关资料。
4. 按任务汇总规则来源、关键约束、允许的验证方式和缺失项。规则冲突按当前工具指令层级及项目声明的适用范围处理；无法判断且影响实施时先确认。
5. 没有项目规范时，以现有实现、工具配置和已确认需求为依据做最小范围工作；涉及协议、安全或数据约束的未知项先确认，不宣称已满足不存在或未取得的团队规范。

## 2. 选择流程

- **代码任务**：按[代码与文档流程](references/change-workflows.md#代码任务)理解调用链、保留兼容性并验证。
- **文档任务**：按[代码与文档流程](references/change-workflows.md#文档任务)确定用途、核对实现并维护引用。
- **认证、安全或持久层变更**：再按[高风险链路检查](references/sensitive-chains.md)读取相关部分；其他任务不强制加载。
- **仅审查**：先报告有依据的问题与验证边界，不因加载本 Skill 自动修改代码或创建评审文件。

可结合当前环境已有的诊断、重构等专用能力；缺少某个工具时使用可用替代方案并说明，不将特定工具或另一 Skill 作为强制依赖。

## 3. 约定改动与验证边界

1. 修改前定位实现、调用方、数据模型及配置读写位置；多模块或多端共享行为须继续查到最终消费方，不能只看入口。
2. 说明需要修改的文件、必须保持的存量行为、异常边界与验证方式。小任务使用简短说明，不机械生成方案文件。
3. 现有调用方依赖的签名、序列化、错误语义和副作用视为兼容面；按项目规定隔离新增行为。确需破坏性变更时，先说明影响、迁移与回滚并取得明确确认。
4. 检查测试时限、环境、依赖、构建限制与当前授权，不因 Skill 推荐验证就运行项目禁止的命令。

## 4. 实施与交付

1. 沿用目标项目的分层、命名、注释语言和日志约定，不把另一项目的后端框架、前端规范或数据规则套过来。
2. 按风险执行新行为与存量回归验证。模型、构造器、序列化及调用方变更需闭环核对；不要因单个调用点正确就宣称全链路可用。
3. 更新受影响的权威文档与索引；项目提供模板时按用途使用，无对应模板时不强行套用。文档目录、名称和章节来自项目规则，不由本 Skill 固定。
4. 仅运行已核实且获授权的检查入口；分清工作区、暂存快照及 CI 基线。没有检查工具时报告可执行的替代验证，不自动安装工具、修改暂存区或创建钩子。
5. 交付时列出实际改动、兼容性影响、执行过的验证和遗留问题；未执行的测试、批准、CI 接入、推送和部署不能写成完成。格式或链接检查通过不等于内容正确、业务通过或安全审查完成。
