# 高风险链路检查

仅在任务涉及下列行为时读取对应章节。具体协议和数据约束以目标项目为准；本文件不授权生产查询、数据变更、提交或部署。

## 认证与安全链路

修改身份、权限、会话、凭据或安全回调前，核查：

1. 业务场景、信任边界、身份与凭据来源、数据归属和生命周期。
2. 校验入口、候选数据及其有效性标准、权限判断和失败语义。
3. 成功副作用、下一跳和最终凭据或结果消费方。
4. 重放、重复/并发、跨节点及多客户端状态的边界；项目涉及多域时再核对域隔离。
5. 新旧版本混用、配置缺失、功能关闭和回滚后的行为。

缓存存在、对象可解析或用户名相同，不足以证明满足下游认证契约。候选有效性必须依据真实消费者判断，不能将不同用途的会话、令牌或缓存视为等价。

验证要覆盖最终消费，不仅检查中间步骤返回成功；至少考虑一个“中间成功、下游因状态不完整或凭据归属错误而失败”的反向用例。终点和凭据语义由目标项目代码确定，不固定接口路径。

区分可用性旁路与必要安全校验。认证、签名、撤销或权限校验失败不能因笼统的“故障放行”被跳过，具体失败与回滚行为按项目要求核实。

## 数据与持久层

修改数据模型、迁移、索引或持久层前，读取项目及目标数据库的规则，不默认使用某一种数据库或 ORM。

- 结合实际引擎核对字段类型、默认值、可空语义和业务初始状态；不能为了格式检查机械添加默认值。
- 根据真实查询、并发写入与状态迁移设计索引和唯一约束，核查历史数据对迁移的影响。
- 数据模型、映射、读写逻辑、序列化及调用方同步核对，避免存储约束与代码不一致。
- 区分热路径与管理写入路径，核查允许的 I/O、事务、一致性与补偿要求；不将一种链路的事务或降级要求套到另一种链路。
- 输出迁移方案与执行迁移是不同授权，未经明确批准不执行生产写入、批量变更或结构迁移。

## 删除与对外行为变化

仍有消费者的接口、字段、配置、脚本或文档属于迁移对象，不是仅凭“旧”就能删除的无用内容。先说明影响、迁移顺序、兼容范围与回滚方式；清理、重构或统一规范不构成改变旧协议的授权。
