# Java 后端基础规范

仅在开发、修复或评审 Java 代码时读取，并结合[公共编码规范](coding-standard.md)执行。先确认项目 Java 版本、框架、模型、数据访问方式与验证限制，不预设 Spring、MyBatis、Lombok 或某种统一响应类。

## 格式与模型

- 优先沿用项目 formatter、Checkstyle、EditorConfig 和相邻文件风格。无明确约定的新文件默认 4 空格缩进、左大括号不换行，控制语句保留大括号；不批量改写旧文件。
- 类与枚举使用 UpperCamelCase，方法和变量使用 lowerCamelCase，常量使用 UPPER_SNAKE_CASE。DTO、VO、PO 等类型缩写在变量名中按普通驼峰处理，名称表达元素与业务含义。
- import 按现有分组排序，新增代码避免通配符 import，清理本次引入的未使用项。接口、Service 和实体命名沿用项目习惯，不强行增设接口或改名。
- 新类用中文 JavaDoc 说明职责；公共方法说明参数、返回值、异常及关键约束。重写方法可继承有效接口文档，只补实现差异，不重复无用描述。
- 数据模型字段说明含义、单位、可空性、默认值和必要枚举。涉及 Builder 或 Lombok 时核查真实字段、构造调用、getter / setter 与序列化，不仅检查调用处。
- 仅使用目标 Java 和框架版本支持的 API；未获授权不升级 JDK、依赖或把已有包体系迁移到另一代框架。

## 分层与接口

- 有 Web 分层时，入口处理参数接收、既有鉴权、必要转换和业务调用，核心业务规则放在负责该规则的业务层，不新增直接跨层的数据写入。
- 新业务逻辑尽量不依赖 Web 请求对象，使用必要的数据传递；存量方法签名和异常仍按兼容要求处理，不为了分层直接破坏调用方。
- 数据访问层专注存取，不隐含权限决策或认证绕过；请求、响应与持久模型按项目约定区分，不把数据库完整实体作为新接口响应。
- 沿用真实 HTTP 方法、路径、响应结构、状态与错误语义，不能把管理端 POST 或某个响应封装作为所有服务的默认协议。

## 数据与并发

- SQL 使用参数绑定，不拼接用户输入；使用 MyBatis 时区分安全参数绑定与文本替换。逻辑删除、分页上限和数据权限按真实模型处理，不机械增加不存在的字段。
- 事务按需要原子提交的业务边界设计；有代理事务时核查自调用、异步和异常捕获对回滚的影响，不认为方法上有注解就一定生效。
- 数据库未提交状态不能提前发布为有效缓存；提交后刷新或失效按项目约定处理，失败保留可观测信息及恢复方式。
- 锁、唯一约束、原子操作或幂等存储按真实并发场景选用既有能力；分布式锁释放验证持有人，不直接删除其他请求的锁。
- 批量读写控制规模并核查行数、部分失败、N+1 与内存占用。金额、时间单位、时区及默认值按业务语义明确，不以格式统一替代正确性。
- 修改 DDL 时同时检查模型、映射、读写及状态迁移；引擎相关类型和约束来自项目，不把某种数据库的自增、默认值或索引规则套到所有项目。

## 日志与测试

- 沿用现有日志框架和参数化写法，不直接序列化可能带凭据的 DTO。异常边界保留原因与关联信息，测试或生产故障信息不得进入响应体。
- 默认使用当前测试框架与 Mock 方式，按风险覆盖新增和存量路径；框架不同不构成引入新测试依赖的理由。
- 构建命令、profile、容器与依赖以实际项目为准；禁止主动构建的项目只做允许的验证并报告缺口，不臆造启动命令或切换打包形态。
