# 公共编码规范

用于代码开发、修复、重构和代码评审，不绑定语言、框架、根包或接口响应类型。项目已有明确工具配置时沿用；没有约定时按下列基础标准处理新增代码，不批量重排无关存量文件。

## 格式与命名

- 先查项目 formatter、lint 和编辑器配置，沿用文件的缩进、括号、引号、换行及 import 分组；语言专用格式按对应规范处理。
- 新文本采用 UTF-8，保留合理的文件换行风格，清理无意义行尾空白并保留末尾换行；自动生成文件按生成工具约定处理，不手改生成结果。
- 名称表达业务意图，遵循语言惯例；避免无意义缩写和编号变量。常量、状态值与枚举优先复用现有定义，不为单个直观表达式制造抽象。
- 简化复杂条件与多层嵌套，优先卫语句。新增或主要改写的方法默认控制在 80 行以内；项目规则更严格时遵循项目要求。拆分保持职责清晰，不为行数制造无用方法或参数透传层，也不顺带拆分未涉及的旧方法。
- 抽象以真实重复和共同业务语义为依据；表面相似但生命周期或失败语义不同的逻辑不要强行合并。

## 中文注释

- 新增公共接口、关键方法和复杂逻辑默认使用中文说明职责、重要输入输出、失败语义及约束；项目已有明确语言或文档工具约定时沿用并说明差异。
- 注释解释业务意图和取舍，不逐行翻译代码。直接赋值、简单判空和直观遍历不机械加注释。
- 去重、分组、交集、差集、批量关联及嵌套集合转换说明输入、维度、顺序、覆盖规则和输出用途；批量任务说明部分失败如何处理。
- 缓存、锁、事务、异步副作用和状态迁移说明真正影响行为的约束，例如有效期、续期、持有人、提交时机、幂等或补偿。
- 修改逻辑时同步核对原注释；删除注释掉的废弃代码，不以注释、占位实现或未完成提示代替交付。作者、审批、测试与上线记录只写已确认事实。

## 日志与异常

- 核心入口、关键分支和结果保留必要业务标识、关联标识、结果与原因；不用打印整个请求或用户对象代替设计日志。
- 异常由负责处理、转换或最终兜底的边界记录，保留必要上下文和定位堆栈；纯透传层不重复打印同一异常，也不吞异常。
- 预期拒绝、过期和重复回调按项目约定选择日志级别，不把正常状态刷成故障；批量处理优先汇总数量、过滤和失败结果，避免循环刷屏。
- 不输出密码、密钥、完整令牌、Cookie、有效验证码或其他认证材料。必要日志字段按项目隐私要求脱敏，不向调用方暴露内部堆栈。
- 只在能够处理或转换的边界捕获异常，不给每个方法机械加 catch，不使用异常控制正常业务流程。

## 兼容性与边界

- 修改前搜索方法、模型、序列化字段、配置和实际调用方，核查正常返回、错误、默认值与副作用；仓库内无引用不证明外部消费者不存在。
- 新行为涉及旧协议时按项目要求隔离实现，不为统一规范直接改变旧调用行为。破坏性调整先说明影响、迁移与回滚并获得批准。
- 删除兼容入口、字段或旧分支前，必须确认无调用、完成必要迁移并获得用户明确批准；证据或授权不足时保留原行为。
- 在负责业务规则的边界校验空值、范围、集合规模和输入合法性。返回值语义应明确，不能为追求“统一”改变已有 null、异常或错误码契约。
- 涉及外部调用时核查超时、重试、幂等和未知结果的处理，不对可能产生副作用的请求盲目重试；不因依赖异常擅自故障放行安全校验。

## 交付自检

- 检查本次范围的格式、命名、未使用 import、无效变量及注释与实现一致性。
- 验证模型声明、构造或 Builder、读写、序列化和消费端闭环；多端存在同名模型时分别核对。
- 按风险验证新增、异常与存量路径；格式、静态检查和业务测试不能互相冒充。只运行已核实且允许的检查入口。
- 后台单元测试使用显式时限，默认最长 60 秒；项目禁止构建或缺少环境时说明验证边界，不安装依赖或关闭检查来制造通过。
- 只读检查不改暂存区、钩子或构建脚本。已有格式化器只在获授权的本次范围使用；本 Skill 本身不会安装或启用格式化和 CI。
